## 4. Functional scope (from the user story)

Story: analista de risco / prevencao a fraudes wants a local backtest that
simulates the current VPN detection rules on historical data, to measure
effectiveness and support decisions. It must NEVER act on production, LDAP,
or sensitive data in real time.

The backtest is read-only and produces a report answering:

- Volume total de casos analisados
- Quantidade de casos classificados como VPN
- Taxa de falso positivo / falso negativo (report as
  "not_available_without_validated_labels" when no labeled dataset is
  configured; do not invent labels)
- Reproducibility: all parameters logged in the report
- Output must be readable by non-technical stakeholders (Markdown + JSON)

Cases to implement against the VPN table:

1. Summary of the period
   - COUNT(*) events, COUNT(DISTINCT user_column) users
   - filter: timestamp_column >= --start AND timestamp_column < --end

2. Users with more than N distinct source or corporate IPs in the period
   (N = --distinct-limit, default 2). Report a sample of offending users
   with their event count and distinct-IP counts.

3. Users with more than N distinct hostnames.

4. Users with more than N distinct device IDs.

5. Users with more than K logins on the same day
   (K = --daily-login-limit, default 10). Group by user + DATE(timestamp).

6. First VPN policy from the HU:
   "Existe sessao ativa para mesma chave com VPN + login atual em rede
    fisica do BB = encerra sessao de VPN no LDAP".
   Simulate elegibility only. Never call LDAP.
   Requires a separately configured "physical login" table (schema, table,
   user column, timestamp column, optional network column + expected value).
   Join VPN and physical tables on trimmed user key with a time window:

     TRIM(v.user_column) = TRIM(p.user_column)
     AND p.timestamp_column >= v.timestamp_column
     AND p.timestamp_column <  v.timestamp_column + <window> HOURS
     AND p.timestamp_column >= ?   -- --start
     AND p.timestamp_column <  ?   -- --end
     AND (optional) TRIM(p.network_column) = ?  -- --physical-network-value

   Window is parameterized by --active-window-hours (1..168, default 8).
   If the physical table is not configured, report the case with
   status="skipped" and an explanatory note. All OTHER cases must still run.

Do not implement Redis integration, LDAP action, ETL, or streaming.

## 10. `rules.py` requirements

- Dataclass `BacktestCaseResult(name, status, count, sample, note="")`.
- Helper `qualified(schema, table) -> "schema.table"`.
- Helper `ts_params(start, end)` returning two "YYYY-MM-DD HH:MM:SS" strings.
- Function `get_table_columns(conn, schema, table)` that:
    1. Tries SYSCAT.COLUMNS with (schema, table) params.
    2. Falls back to SYSIBM.SYSCOLUMNS with (TBCREATOR, TBNAME) params.
    3. Returns list[str] of uppercase column names in COLNO order.
- Function `validate_columns(conn, schema, table, required_columns)` that
  raises ValueError if any required column is missing, and the message must
  name the missing columns AND list the available ones. Do not let raw
  `SQL0206N` bubble up.
- Function `validate_configured_tables(conn, cfg)` that validates the VPN
  table columns and, if configured, the physical table columns.
- Function `run_summary(conn, cfg) -> dict` returning:
    total_events_analyzed, total_users_analyzed, vpn_classified_cases,
    false_positive_rate, false_negative_rate
  The two rates are the string
  "not_available_without_validated_labels".
- Function `run_distinct_limit_case(conn, cfg, name, columns, note)` that:
    - groups by TRIM(user_column)
    - HAVING any COUNT(DISTINCT NULLIF(TRIM(column), '')) > cfg.distinct_limit
    - orders by EVENTS DESC
    - `FETCH FIRST cfg.sample_limit ROWS ONLY`
    - reports both the count of qualifying users (via a wrapping
      COUNT subquery on the same SQL) and the sample rows.
- Function `run_daily_volume_case(conn, cfg)`:
    - groups by TRIM(user_column), DATE(timestamp_column)
    - HAVING COUNT(1) > cfg.daily_login_limit
    - top N sample by LOGIN_COUNT DESC
- Function `run_active_vpn_plus_physical_login_case(conn, cfg)`:
    - if physical table missing -> status="skipped".
    - otherwise, join per section 4 formula.
    - the network filter is an extra "AND TRIM(p.<col>) = ?" only when
      both network_column and network_value are configured.
- Function `run_backtest_cases(conn, cfg)`:
    1. calls validate_configured_tables
    2. computes metrics = run_summary
    3. builds the list of 5 cases (three distinct-limit variants for IPs,
       hostnames, devices; the daily-volume case; the physical-login case).
    4. returns (metrics, cases).

All SQL identifiers must be interpolated only AFTER passing the identifier
regex. Only literal values are bound with `?`.

- Defaulting the user column to `CD_USU`. The correct default is `CD_USU_AUT`.

- Leaking the DB2 password in `.env.example`, README examples, or logs.
- Trying to detect the catalog dialect at runtime by string sniffing the
  server; always try SYSCAT first, fall back to SYSIBM.
- Using bashisms in a `#!/usr/bin/env sh` script.
